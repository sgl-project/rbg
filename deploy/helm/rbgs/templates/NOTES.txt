NOTE: the deprecated workload types are DISABLED (controller.deprecatedWorkloadTypes.enabled=false).
Deployment, StatefulSet, and LeaderWorkerSet are rejected on every create and update,
with no exemption for objects that already use one. This setting is only valid for a
fresh installation: the controller holds no RBAC for these types and watches none of
them, so it cannot reconcile such an object. A migration path will be provided later.
WARNING: the v1alpha1 schema defaults spec.roles[].workload to apps/v1 StatefulSet,
so a new v1alpha1 object is rejected even if it never sets `workload`. To keep using
v1alpha1, every role must set workload.apiVersion=workloads.x-k8s.io/v1alpha2 and
workload.kind=RoleInstanceSet; submitting the object as v1alpha2 does this by default.
To re-enable them, set controller.deprecatedWorkloadTypes.enabled=true.
{{- else }}
NOTE: the deprecated workload types are ENABLED (controller.deprecatedWorkloadTypes.enabled=true).
Deployment, StatefulSet, and LeaderWorkerSet workload types are supported, but
deprecated: migrate roles to RoleInstanceSet (the v1alpha2 default).
{{- end }}
